INTRODUCTION                                        *snippetary*

vim-snippetary is a snippet engine for Vim and Neovim that reads
UltiSnips-format |UltiSnips| snippet files but is written entirely in
classic vimscript: no Python and no |text-properties| are required, so
it also runs in minimal builds.

SETUP                                     *snippetary-setup*

The plugin loads itself on startup. Snippet files are looked up in the
directories listed in |g:snippetary_snippet_dirs| (default: ['UltiSnips'],
or g:UltiSnipsSnippetDirectories when defined). Files inside those
directories are recognized as `ft.snippets`, `ft_*.snippets`,
`ft/*.snippets`, and the all-filetypes scope `_.snippets` (also honored
under its legacy names `all.snippets`, `all_*.snippets` and `all/`; the
native `_.snippets` wins when both exist). `extends` chains are followed.

While a `*.snippets` file is loaded its filetype is set to `snippets`
with matching syntax support if available.

USAGE                                     *snippetary-usage*

Type a snippet trigger and press |g:snippetary_expand_trigger| (default
<tab>). The engine expands the snippet, selects the first tabstop in
selection mode and keeps mirrors in sync while you type. <tab> again
jumps to the next tabstop; |g:snippetary_jump_backward_trigger|
(default <s-tab>) jumps backward. Reaching the ${VISUAL} position or a
tabstop 0 (or jumping backward from the first stop) ends the session.
Editing somewhere outside the running tabstop abandons the session; the
buffer text is always left as plain text.

${VISUAL} inserts the text captured by the last visual selection made
with the expand trigger in visual mode (the text is cut from the
buffer).

MAPPINGS                                  *snippetary-mappings*

The plugin defines these <Plug> mappings; default user maps are created
for <tab>/<s-tab>:

  <Plug>(snippetary-next-or-trigger)   expand/jump next (insert+select)
  <Plug>(snippetary-back)              jump backward (insert+select)
  <Plug>(snippetary-visual)            capture visual for ${VISUAL}

Snippet-file syntax                       *snippetary-syntax*

    snippet trigger ["description" ["options"]]
      lines of body, with leading tabs and indented lines kept
    endsnippet

Block ends (`endsnippet`, `endglobal`) and directives may be written
with leading indentation (UltiSnips `line.strip()` semantics); body
lines keep their raw indentation as literal text. UltiSnips-format
only, no snippet inheritance from SnipMate.

Options understood: w (word boundary), i (in-word match),
b (only whitespace may precede the trigger), m (strip trailing
whitespace), t (keep literal tabs), x (exit insert after the last
tabstop). `r`/`e` snippets must be skipped for now.

Directives: priority N, extends ft[,ft...], global ... endglobal
(python content is skipped silently), clearsnippets, context.

Escapes follow UltiSnips: backslash escapes { } $ and backtick; $$ is
an escape for a literal dollar.

Shell (`!v`) interpolations run `eval()` on the expression. String
results are inserted raw, other types via string(). Two context
variables mirror the UltiSnips python t[n] analog:

- b:snippetary_t: dictionary of tabstop texts. Stops that already
  rendered hold their current text; pending stops hold their
  pre-rendered default text (UltiSnips t[n] semantics: t[n] holds the
  INITIAL tabstop text even before the stop itself renders).
- b:snippetary_visual: the text captured by the last visual selection
  (the same text ${VISUAL} receives, \r stripped). It is set once per
  expansion and kept until the next expansion.

REGEX TRIGGERS                                *snippetary-regex*

With the 'r' option the trigger is a python-re subset regular
expression. Matching follows the UltiSnips engine: the pattern is
re.finditer()d over the text before the cursor (line start to
cursor) and the snippet fires on the first match whose end equals
the cursor position; only the matched span is removed before the
body expands, with the option 'b' applying relative to that span.

Supported grammar: literals, '.', anchors (^ $ \A \Z), word
boundaries (\b \B), shorthand (\s \S \d \D \w \W), character
classes with ranges, negation and shorthand inside, groups ((...),
(?:...), (?P<name>...)), alternation, quantifiers (* + ? {m} {m,}
{m,n} and lazy forms), lookahead ((?=...) (?!...)) and fixed-width
lookbehind ((?<=...) (?<!...)). Inline flags: (?i) at pattern start
and (?i:...) groups. Anything else makes the pattern fail closed
(the snippet never matches, like the python-skip degradation; the
last compile error is left in g:snippetary_re_error).

The matches of capture groups are available to !v interpolations
through b:snippetary_match: a dictionary with the whole match in
key 0 and the groups in keys 1..n (groups that did not match are
absent; the python analog is match.group(n)):
>
    snippet "(\\w+).par" "Parenthesis (postfix)" r
    (`!v b:snippetary_match[1]`$1)$0
    endsnippet
<

COMMANDS                                  *snippetary-commands*

:SnippetaryReload   reread snippet files and reset sessions
:SnippetaryClean    end all snippet sessions in the current buffer
:SnippetaryVersion  print the version
:SnippetaryEdit [scope]
                    open the snippet file of {scope} (default: the first
                    filetype of the buffer; '_' = all filetypes). The first
                    existing file found in |g:snippetary_snippet_dirs| is
                    opened, otherwise the file is placed (and created on
                    write) in the first directory.
:SnippetaryEditGlobal
                    open the all-filetypes snippet file.

Editing snippet files triggers a reload on write. Normal-mode helper:
snippetary#goto_definition() opens the file defining the snippet for the
keyword under the cursor (the last word before the cursor when the
cursor is not on a keyword; the text before the cursor is still probed
for multi-word triggers) and places the cursor on the `snippet` header
line; without a match it falls back to |SnippetaryEdit|.

COC-ULTISNIPS                            *snippetary-coc*

autoload/UltiSnips.vim provides UltiSnips-API shims
(UltiSnips#SnippetsInCurrentScope, UltiSnips#ExpandSnippet) backed by
snippetary, and the plugin announces g:did_plugin_ultisnips (only when
the real UltiSnips has not). The coc-ultisnips extension then serves
the buffer's triggers inside the coc completion popup (merged with the
language-server items) and expanding an accepted snippet runs through
snippetary. When the real UltiSnips is re-enabled, remove the shim file.

LIMITATIONS                              *snippetary-limitations*

Python interpolation (!p) is skipped; transforms are dropped (the
tabstop or mirror is kept); choice lists become their first choice;
the eval-option trigger ('e') does not match; regex triggers support
the python-re subset documented in |snippetary-regex| (lookbehind
only with fixed width; backreferences, (?x) verbose patterns and
unsupported escapes make the snippet fail closed, never matching);
multi-line typing is tracked at the extent level only.
